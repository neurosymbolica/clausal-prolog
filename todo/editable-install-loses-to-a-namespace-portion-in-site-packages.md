# The editable install of `clausal` loses to a namespace portion in site-packages

**Filed:** 2026-07-30, found while merging the SMT prover's `P.key` support.
**Status: DIAGNOSED, NOT FIXED. Masked everywhere by a `PYTHONPATH` convention.**

## What happens

In `/workspace/clausal/venv`, with nothing on `PYTHONPATH`:

```
$ cd /tmp && /workspace/clausal/venv/bin/python -c "import clausal; print(clausal.__file__)"
None
$ ... -c "from clausal import Var"
ImportError: cannot import name 'Var' from 'clausal' (unknown location)
```

`clausal` binds to a **namespace package**, not the real one. Every attribute the
real `clausal/__init__.py` exports — `Var`, `solve`, the lot — is simply absent.

## Why

`site-packages/clausal/` exists as a directory with **no `__init__.py`**, because
`clausal_jax` and `clausal_torch` install their wrappers into
`site-packages/clausal/modules/`. That directory is legitimate and load-bearing —
see "Do not delete it" below.

The editable install is supposed to win anyway, and it cannot, because of *where*
setuptools puts its finder:

```python
# site-packages/__editable___clausal_0_3_1_finder.py
def install():
    if not any(finder == _EditableFinder for finder in sys.meta_path):
        sys.meta_path.append(_EditableFinder)      # <-- append, not insert
```

Observed `sys.meta_path`:

```
0 DistutilsMetaFinder   1 BuiltinImporter   2 FrozenImporter
3 PathFinder        <- scans sys.path, finds site-packages/clausal/, answers with a namespace spec
4 _EditableFinder   <- MAPPING = {'clausal': '/workspace/clausal/clausal'}, never reached
```

`PathFinder` sits *ahead* of the editable finder. It scans `sys.path`, finds a
directory named `clausal` with no `__init__.py`, and — since no regular `clausal`
is anywhere on `sys.path` (the real one is reachable only through the finder at
index 4) — returns the namespace spec. The mapping that would have given the real
package is never consulted.

So the append-based editable install is only correct while nothing on `sys.path`
shadows the distribution name. `clausal_jax` / `clausal_torch` create exactly
that shadow.

## Why nobody has noticed

Every runner puts `/workspace/clausal` on `PYTHONPATH` explicitly — e.g.
`au/firb/run_tests.sh:18` builds
`PYTHONPATH="/workspace/clausify/kit:/workspace/clausify:/workspace/clausal:$REPO_ROOT..."`.
That puts the real, *regular* package on `sys.path`, and a regular package beats a
namespace portion regardless of scan order, so `PathFinder` returns the right
thing and the bug stays invisible.

It surfaces the moment a caller omits that entry. `/workspace/clausify`'s
`auto/tests` did: five `test_gate_*` modules failed to *collect*, and pytest
**interrupted the whole run — 890 tests did not execute**. That reads as a short
error block, not as a non-run, which is how it nearly got mistaken for a
regression from an unrelated merge.

## Do NOT "fix" it by deleting `site-packages/clausal/`

Its 15 files are the installed content of the `clausal_jax` and `clausal_torch`
distributions (confirmed from their `dist-info/RECORD`), and
`clausal/modules/__init__.py` **deliberately appends that directory to its own
`__path__`** so separately-installed wrapper distributions are discoverable:

```
clausal.modules.__path__ == ['/workspace/clausal/clausal/modules',
                             '/workspace/clausal/venv/.../site-packages/clausal/modules']
clausal.modules.jax   -> .../site-packages/clausal/modules/jax.py   # works today
```

Deleting the directory breaks both wrappers and strands their `dist-info`, so pip
still reports them installed. If they ever must go it is
`pip uninstall clausal-jax clausal-torch`, never `rm`.

## Options

1. **Reinstall editable in compat mode** —
   `pip install -e /workspace/clausal --config-settings editable_mode=compat`
   emits a plain path-`.pth` that puts `/workspace/clausal` on `sys.path` instead
   of relying on a meta-path finder. The real regular package then beats the
   namespace portion the same way the `PYTHONPATH` convention already does.
   Smallest change; already proven to work, since that is exactly what setting
   `PYTHONPATH=/workspace/clausal` does today.
2. **Repackage the wrappers** so they no longer install into `clausal/modules/` —
   an entry-point or a distinct top-level the `modules/__init__.py` discovers.
   Removes the shadow at its source, but touches two other distributions and the
   discovery code.
3. **Leave it, document the convention.** Runners already set `PYTHONPATH`
   correctly; write the requirement down where a new caller will see it rather
   than rediscovering it through a zero-test run.

Option 1 first. It is one command and reversible.

## Verification, whichever is chosen

From a directory that is *not* a Clausal checkout, with `PYTHONPATH` unset:

```
cd /tmp && /workspace/clausal/venv/bin/python -c "import clausal; print(clausal.__file__)"
# must print /workspace/clausal/clausal/__init__.py — NOT None

cd /tmp && /workspace/clausal/venv/bin/python -c "import clausal.modules.jax, clausal.modules.torch; print('wrappers ok')"
# the wrappers must still resolve, i.e. the __path__ extension still works
```

Then re-run `au/firb/run_tests.sh` and the clausify `auto/tests` suite: this venv
backs every domain suite, so the change is low-risk to make and high-blast-radius
to get wrong. Do it deliberately, not alongside other work.
