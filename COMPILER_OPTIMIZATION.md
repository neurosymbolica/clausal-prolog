## Part 1 — The existing system

### 1.1 What the compiler does

The compiler (`clausal/logic/compiler.py`) translates clausal predicate
definitions into Python generator functions. Given a predicate like:

```
Reach(X, Y) <- Edge(X, Y)
Reach(X, Y) <- (Edge(X, Z), Reach(Z, Y))
```

it emits a Python function `Reach__2(this_generator, _tramp_parent, arg0,
arg1, trail)` whose execution model is:

- **yield `(_tramp_parent, None)`** at each solution (suspending until the
  calling generator asks for more)
- **yield `(_tramp_parent, _DONE)`** when all clauses are exhausted
- **stack-safe**: sub-predicate calls use a coroutine handoff instead of
  direct Python calls, so recursion depth never grows the Python call stack

This is the **trampoline protocol**. It is driven by
`clausal/logic/trampoline.py`, which iterates a chain of generators without
nesting Python frames.

### 1.3 The trampoline protocol

Every compiled predicate function has this signature and shape:

```python
def Predicate__N(this_generator, _tramp_parent, arg0, …, argN-1, trail):
    # ... clause match arms ...
    yield (_tramp_parent, _DONE)
```

`this_generator` is a `StepGenerator` that wraps this function and passes
itself as `this_generator` automatically.  `_tramp_parent` is the
`StepGenerator` of the calling predicate — the entity to notify of solutions
and exhaustion.

**Solution:** `yield (_tramp_parent, None)` — suspends; the trampoline loop
will send `None` back when the parent wants the next solution.

**Exhaustion:** `yield (_tramp_parent, _DONE)` — the final statement in every
function; tells the calling generator the clause list is exhausted.

**Sub-predicate call** (the stack-safe pattern, generated by
`_compile_predicate_call_trampoline`, compiler.py:2992):

```python
_gen1 = StepGenerator(Foo._get_dispatch(), this_generator, arg_a, arg_b, trail)
_st1 = (yield (_gen1, None))          # hand control to child
while _st1 is not _DONE:
    <continuation: rest of clause body, ending in yield (_tramp_parent, None)>
    _st1 = (yield (_gen1, None))      # ask child for next solution
```

Instead of calling `Foo__2(...)` directly (which would add a Python frame),
this creates a `StepGenerator` child and yields a reference to it.  The
trampoline's outer loop (`trampoline.py:96`) receives `(_gen1, None)`, sends
`None` to `_gen1`, gets back `(this_generator, None)` when a solution is
found, and sends `None` to `this_generator` so the while-loop body runs.
No Python stack growth occurs no matter how deep the recursion.

### 1.5 The groundness-keyed dispatch layer (V2-2)

When a predicate has enough clauses and a sufficiently selective argument
position, `_analyze_index_positions` (compiler.py:4643) partitions the
clauses into buckets keyed by first-argument value and compiles each bucket
into its own sub-function.  A dispatch closure then routes calls:

```python
# _make_groundness_dispatch_trampoline (compiler.py:4766)
def dispatch(*args):
    parent = args[1]
    _a = deref(args[pos + 2])   # check the indexed arg
    if is_var(_a):
        yield from fallback_fn(*args)   # arg unbound: try all clauses
    else:
        try:
            _bfn = idx_dict.get(_a)
        except TypeError:
            _bfn = None
        if _bfn is not None:
            yield from _bfn(*args)      # exact match: only this bucket
        else:
            yield from default_fn(*args)  # no match: try default clauses
    yield (parent, _DONE)
```

Each of `fallback_fn`, `_bfn`, and `default_fn` is itself produced by
`_build_predicate_trampoline_funcdef`, so they all share the per-clause
`deref` problem.

## Part 2 — Identified inefficiencies

### 2.1 Per-clause `deref()` repetition (highest impact)

**Location:** `_build_predicate_trampoline_funcdef`, compiler.py:3420–3424

Each clause generates its own `ast.Match` statement. The subject of every
match is:

```python
subject = ast.Tuple(
    elts=[_call(_name("deref"), _name(n)) for n in arg_names],
    ctx=ast.Load(),
)
```

So for a predicate with N clauses and K arguments, the emitted function calls
`deref()` N×K times per invocation, on the same arguments.  `deref` is fast
(it is a C extension), but it is not free, and for a fact table with many
clauses (e.g. `Edge/2` above with 3 clauses) or a predicate with many
arguments the overhead adds up on every call site.

The arguments cannot change between match statements because no binding occurs
during a failed match — the only bindings that happen are inside the `try:`
block, and those are undone by `trail.undo(_mark)` in the `finally:` before
falling through to the next match.  Dereffing once before all the matches is
therefore semantically identical.

### 2.2 Separate match per clause instead of unified match (structural)

Related to 2.1: the N separate `ast.Match` nodes are also a structural
redundancy.  Python's `match` statement can hold any number of `case` arms;
the current code uses one `match` per clause rather than one `match` for all
clauses.  Consolidating into a single `match` has two benefits:

- Eliminates the N redundant match-subject expressions entirely (not just
  their `deref` component)
- Lets Python's match engine see all patterns at once, enabling its own
  structural dispatch (relevant groundwork for Phase 5 deep indexing)

### 2.3 Duplicate branch compilation in reified ITE

**Location:** `_compile_reified_ite_eq_trampoline`, compiler.py:3100–3116

The function compiles the then/else branches **twice** each:


`unify_branch` and `dif_branch` are used in the `undetermined` block for

### 2.4 Redundant `trail.mark()` in disjunction

**Location:** `compile_goal_trampoline`, Or case, compiler.py:2722–2738

Generated code for `goal1 ; goal2`:

```python
_m = trail.mark()
<left_stmts>            # try left branch
trail.undo(_m)
_m = trail.mark()       # ← no-op: trail is already at _m
<right_stmts>           # try right branch
trail.undo(_m)
```

After `trail.undo(_m)`, the trail top is exactly `_m`.  Calling
`trail.mark()` again returns the same value.  The second `_assign_mark` emits
a redundant store on every disjunction.

### 2.5 Three separate clause traversals at compile time

**Location:** `compile_predicate_trampoline`, compiler.py:3565–3569

```python
base_globals.update(_collect_head_types(clauses))   # recursive walk 1
base_globals.update(_collect_py_thunks(clauses))    # recursive walk 2
_inject_call_targets(clauses, base_globals, db, globals_)  # walk 3
```

Each function independently traverses the entire clause/term tree.  All three
collect different kinds of leaf objects (term classes, PyThunk lambdas, Call
targets) that could be gathered in a single pass.

### 2.6 `._get_dispatch()` called at runtime on every invocation

**Location:** `_dispatch_call_iter_trampoline`, compiler.py:2559–2573

Every `StepGenerator` construction in generated code does:

```python
_gen = StepGenerator(Foo._get_dispatch(), this_generator, arg0, arg1, trail)
```

`_get_dispatch()` is an attribute lookup plus a method call on the
`PredicateMeta` class. For locked (non-dynamic) predicates the result never
changes, so this is wasted work on every predicate call site. For dynamic
predicates (marked with `-dynamic`) it must remain live.

### Phase 1 — Deref-once in match subjects ✓ DONE

**Target:** `_build_predicate_trampoline_funcdef`, compiler.py:3388–3456

**What changes:** Instead of repeating `deref(arg_i)` in every clause's match
subject, emit one deref assignment per argument before the clause loop, then
reference those locals in all subsequent match subjects.

**Before** (current — `Edge/2` with 3 clauses):



### Phase 4 — ~~Merge per-clause matches into a single match~~ INVALID

**Status: Design error — do not implement.**

Python's `match` statement has first-match-wins semantics: once a case arm
matches, the remaining arms are skipped.  Clausal predicates require all
clauses to be tried in order (each clause is an independent generator arm
that can yield multiple solutions and then fall through).  The two semantics
are incompatible for any predicate with overlapping patterns (wildcards,
variables), which is the common case.

Merging N clauses into one `match` with N arms would cause only the first
arm to ever execute when patterns overlap — breaking every multi-clause
predicate with wildcard heads.

The separate-`match`-per-clause structure is the correct and necessary
encoding.  Optimisation of dispatch must happen *outside* the
per-clause match (as V2-2 already does) or via genuinely exclusive
structural patterns (Phase 5 deep indexing, which generates explicit
`if isinstance(...)` guards before each exclusive clause group).

### Phase 4 (replacement) — Merge per-clause matches into a single match

**Target:** `_build_predicate_trampoline_funcdef`, compiler.py:3388–3456
(depends on Phase 1)

**Revised scope:** Only merge clauses whose head patterns at the indexed
position are *mutually exclusive* — i.e., clauses that V2-2 would put in
different buckets.  This is essentially Phase 5 (deep indexing) at a smaller
scale.  Defer to Phase 5.

**What changes:** After Phase 1, the generated code has separate `match
(_d0, _d1):` blocks for each clause. These can be collapsed into one `match`
with multiple `case` arms, eliminating the repeated subject expressions
entirely.

**Before** (after Phase 1):

```python
def Edge__2(this_generator, _tramp_parent, arg0, arg1, trail):
    _d0 = deref(arg0)
    _d1 = deref(arg1)
    match (_d0, _d1):          # match node 1 — subject repeated
        case [_v5, _v6]: ...
    match (_d0, _d1):          # match node 2 — subject repeated
        case [_v7, _v8]: ...
    match (_d0, _d1):          # match node 3 — subject repeated
        case [_v9, _v10]: ...
    yield (_tramp_parent, _DONE)
```

**After:**

```python
def Edge__2(this_generator, _tramp_parent, arg0, arg1, trail):
    _d0 = deref(arg0)
    _d1 = deref(arg1)
    match (_d0, _d1):          # single match node
        case [_v5, _v6]: ...   # clause 1
        case [_v7, _v8]: ...   # clause 2
        case [_v9, _v10]: ...  # clause 3
    yield (_tramp_parent, _DONE)
```

For `Reach__2`, the two arms cover different variable bindings and body
goals; they are separate `case` blocks within the one `match` and do not
interfere with each other.

**Implementation steps:**

1. Change the per-clause `for` loop in `_build_predicate_trampoline_funcdef`
   to collect `case_arm` objects into a list instead of appending `ast.Match`
   nodes to `all_stmts`:
   ```python

   for clause in clauses:
       var_context = {}
       _head_arg_patterns(clause.head, var_context, arity)
   ```

3. Handle `arity == 0` (no match subject needed) and `clauses == []`

4. Apply the equivalent transformation to `_build_predicate_simple_funcdef`.
5. Run: `pytest` — all tests must pass.

### Phase 5 — Deep indexing via structural pattern trie ✓ DONE

**Target:** new helper `_build_pattern_trie`, called from
`_build_predicate_trampoline_funcdef` after Phase 4

**Background:** The current groundness-keyed dispatch (V2-2) answers one
question at the dispatch-closure level: "is arg_i ground, and if so what
value?"  It routes the entire argument value to a pre-compiled bucket.  This
works well for atoms and integers but does not discriminate on structure (e.g.
`[]` vs `[_|_]` vs a compound term).

Deep indexing generates an explicit decision tree *inside* the compiled
function that checks the type and functor of the dereffed argument before
falling into clause match arms.  The result for a list-processing predicate
would look like:

```python
def member__2(this_generator, _tramp_parent, arg0, arg1, trail):
    _d0 = deref(arg0)
    _d1 = deref(arg1)
    # Structural trie over arg1 (the list)
    if isinstance(_d1, list):
        if _d1:                        # [H|T] — non-empty list clauses only
            match (_d0, _d1):
                case [_v0, [_h, *_t]]: ...
        else:                          # [] — base-case clauses only
            match (_d0, _d1):
                case [_v1, []]: ...
    elif is_var(_d1):
        match (_d0, _d1):              # unbound: all clauses
            case ...: ...
            case ...: ...
    yield (_tramp_parent, _DONE)
```

This avoids trying list-base-case arms when the argument is a cons cell, and
vice versa — O(1) dispatch for the common case.

**Implementation plan:**

1. Implement `_classify_head_pattern(head_term, pos) -> str` that returns a
   structural key for the argument at position `pos`: `"nil"`, `"cons"`,
   `"atom"`, `"int"`, `"compound:f/n"`, `"var"` (wildcard), etc.

2. Implement `_build_pattern_trie(clauses, arity, pos) -> dict` that
   partitions clauses by structural key at `pos`, similar to
   `_build_arg_index` but based on type/functor rather than ground value.

3. In `_build_predicate_trampoline_funcdef`, after collecting `case_arms`,
   call `_build_pattern_trie` on the most selective position. If the trie
   has more than one non-var bucket:
   - Generate `isinstance`/`is_var` guards wrapping subsets of `case_arms`
   - Fall back to the flat list for variable-headed arguments

4. The "var" bucket (wildcard clauses) must always be tried, so its arms
   appear in every structural branch.

5. Maintain the existing V2-2 groundness-keyed dispatch as the outer layer;
   deep indexing is the inner layer, applied within each bucket function.

6. Run: `pytest tests/test_search.py tests/test_builtins.py` in addition to
   the full suite.

**Dependencies:** Phases 1 and 4 must be complete first. Phase 1 establishes
the `_d_i` locals that Phase 5 uses in `isinstance(_d1, list)` guards. Phase
4 establishes the single `ast.Match` container that Phase 5 restructures.

### Phase 8 — Body-to-head unification lifting in indexed bucket functions ✓ DONE

**Target:** Indexed bucket compilation loop, `compile_predicate_trampoline`,
compiler.py:3951–3965

**Background:** The `.clausal` term rewriter normalises every clause head to
all-Var arguments, moving ground values into body `Unify` goals.  A fact
`Edge(1, 2)` is stored as:

```
head = Edge(arg_0=Var(_5), arg_1=Var(_6))
body = [Unify(left=Var(_5), right=1), Unify(left=Var(_6), right=2)]
```

When V2-2 groundness dispatch compiles the **bucket function** for arg_0 = 1,
the compiled clause still contains `unify(_v5, 1, trail)` — a call that is
guaranteed to succeed (because the dispatch already confirmed arg_0 is 1) and
therefore wastes a `trail.mark()` + `unify()` + `trail.undo()` triple.

**What changes:** For each bucket function at indexed position `pos` with
bucket key `val`, apply `_lift_clause_at_pos(clause, pos)` to each clause
before building the funcdef.  The helper:

1. Finds the `Unify(Var_at_pos, val)` goal in the clause body's clean prefix
   (a contiguous run of `Unify` goals before the first non-`Unify` goal).
2. Replaces `Var_at_pos` in the head with `val`.
3. Removes that `Unify` goal from the body.

The resulting clause has a concrete term (`val`) at head position `pos`,
causing `head_to_match_pattern` to emit a `MatchValue` (or `MatchClass` for
compound terms) pattern instead of a wildcard capture.  The now-absent body
`Unify` eliminates the mark/unify/undo triple.

**Safety:** Bucket functions are called **only when arg_pos is already ground**
(guaranteed by `_make_groundness_dispatch_trampoline`).  The fallback function
(called for unbound args) always uses the **original, unlifted** clauses, so
unbound-argument queries remain fully correct.

**Before** (bucket for `Edge/2`, arg0 = 1):

```python
def Edge__p0_b0(this_generator, _tramp_parent, arg0, arg1, trail):
    _d0 = deref(arg0)          # = 1, guaranteed by dispatch
    _d1 = deref(arg1)
    match (_d0, _d1):
        case [_v5, _v6]:
            _mark = trail.mark()
            try:
                _m14 = trail.mark()
                if unify(_v5, 1, trail):   # always succeeds — wasted
                    _m13 = trail.mark()
                    if unify(_v6, 2, trail):
                        yield (_tramp_parent, None)
                    trail.undo(_m13)
                trail.undo(_m14)           # wasted
            finally:
                trail.undo(_mark)
    ...
```

**After** (Phase 8 lifts `Unify(Var5, 1)` into the head):

```python
def Edge__p0_b0(this_generator, _tramp_parent, arg0, arg1, trail):
    _d0 = deref(arg0)          # = 1, matches MatchValue(1) below
    _d1 = deref(arg1)
    match (_d0, _d1):
        case [1, _v6]:          # MatchValue(1) — always matches in bucket
            _mark = trail.mark()
            try:
                _m13 = trail.mark()
                if unify(_v6, 2, trail):   # still needed: arg1 may be unbound
                    yield (_tramp_parent, None)
                trail.undo(_m13)
            finally:
                trail.undo(_mark)
    ...
```

**Eliminated per clause per call in the bucket path:**
- 1 × `trail.mark()` (_m14)
- 1 × `unify(_v5, 1, trail)` (guaranteed-succeed)
- 1 × `trail.undo(_m14)`
- 1 nesting level in the try block

**Implementation steps:**

1. Add `_lift_clause_at_pos(clause: Clause, pos: int) -> Clause` near
   `_get_head_arg` (compiler.py:3583).  The function:
   - Extracts the head arg at `pos`; returns `clause` unchanged if it is not
     an unbound Var.
   - Scans `clause.body` left-to-right through the clean prefix (stops at the
     first non-`Unify` goal).
   - Looks for `Unify(Var_vid, term)` or `Unify(term, Var_vid)` where
     `Var_vid._id == head_arg._id` and `term` is not itself an unbound Var.
   - Returns a new `Clause` with `term` at head position `pos` and the
     matching `Unify` removed from the body.

2. In the indexed bucket loop (`compile_predicate_trampoline`, lines
   3953–3959), transform each bucket's clauses before building the funcdef:
   ```python
   for key, bucket_clauses in index["buckets"].items():
       lifted_bucket = [_lift_clause_at_pos(cl, pos) for cl in bucket_clauses]
       # Supply any new head types introduced by lifting to base_globals
       _lifted_ht, _, _ = _collect_globals_info(lifted_bucket)
       base_globals.update(_lifted_ht)
       bname = f"{functor}__p{pos}_b{len(idx_dict)}"
       bdef = _build_predicate_trampoline_funcdef(
           bname, arity, lifted_bucket,
           _effective_db, body_compiler, emit_done=False,
       )
       idx_dict[key] = functiondef_to_function(bdef, globals_=base_globals)
   ```
   The fallback function (line 3943) and the per-position default function
   (line 3960) continue to use the **original** `clauses` / `index["defaults"]`
   — no change.

3. Run: `pytest` — all tests must pass.  Use the visualiser to confirm bucket
   functions show `case [1, _v6]:` instead of `case [_v5, _v6]:` for ground
   facts.

**Note on globals:** For simple scalar lifts (int, str, atom — the common
case), `_lifted_ht` is empty and `base_globals.update` is a no-op.  For
compound-term lifts (e.g. `X = f(A, B)` → head contains `f(A, B)`), the
helper's class is added to globals so that the emitted `MatchClass` pattern
compiles correctly.

## Part 4 — Suggested implementation order

| Phase | What | Type | Complexity | Priority |
|-------|------|------|------------|----------|
| 2 | Fix duplicate ITE branch compilation | Compile-time bugfix | Trivial | High (correctness-adjacent) |
| 3 | Remove redundant Or mark | Runtime: 1 op per disjunction | Trivial | Low |
| 1 | Deref-once in match subjects | Runtime: N×K → K deref/call | Small | High |
| 4 | Single match per predicate | Structural cleanup + trie prep | Small | Medium |
| 6 | Merge clause traversal passes | Compile-time | Medium | Medium |
| 7 | Cache dispatch for locked predicates | Runtime: attr lookup per call | Medium | Medium |
| 8 | Body-to-head unification lifting | Runtime: 3 ops/clause in buckets | Small | Medium |
| 5 | Deep indexing via pattern trie | Runtime: O(1) structural dispatch | Large | High (long term) |

Phases 2 and 3 are trivial one-liner fixes; do them first to clear the
backlog.  Phase 1 is the highest-value runtime change and is the prerequisite
for Phase 4.  Phase 4 is the prerequisite for Phase 5.  Phases 6 and 7 are
independent and can be interleaved anywhere after Phase 1.
