## Method

* **Population.** Every tracked `.pl` file (`git ls-files '*.pl'`), plus each
  ```` ```prolog ````/```` ```pl ```` block of `README.md` and `docs/*.md`,
  written to a temp directory outside the tree. `clausal/library` and `clausal/examples` hold no
  `.pl` file today (both are `.seam`), so those populations are empty.
* **Two children per file**, one per front end, each with
  `CLAUSAL_PL_FRONTEND` set and its own empty `PYTHONPYCACHEPREFIX`. Before it
  loads anything, each child records the front end it resolved and
  `clausal.__file__`. The parent rejects a row, refusals included, whose front
  end is not the one requested or whose engine is not under `--root`, as well
  as one where the wrong loader ran. Core dumps are off in every child.
  The file's directory, and the directory above each enclosing package, go on
  `sys.path`.
* **Compared:** load or refusal; the `test/1` and `test(Name, fail)` verdicts
  by name; for a file without tests, the all-answers of each predicate it
  defines with arity <= 3, called with fresh variables. Each call is capped at
  200 answers. Each test and each call runs in its own forked child, which is
  killed after 30 s. A timeout is recorded as the value `timeout`. It is never
  a translator-vs-native difference row, but it is pinned and compared like any
  other value: under `--check` or `--update`, a side that times out where the
  fixture pins an answer is re-run once, and a second timeout against a pinned
  answer, or an answer against a pinned timeout, is red. A probe that exceeds
  its own limit (10 × the call limit) is killed with its whole process group,
  and each call child also has an alarm backstop, so no call child outlives
  it. A crash costs one item, not the file. Answers are `term_writeq` text with
  local variable names.
* **Oracle.** For each difference: Scryer core
  (`/workspace/scryer-prolog`), then Trealla (`/workspace/trealla-prolog/tpl`).
  For a load difference, does the system consult the file without an error? A
  warning, such as a singleton, does not count. For a test difference, the
  verdict of `test(Name)`, or of `\+ test(Name, fail)`, through the file's
  module. For an answer difference, a failure-driven `writeq` loop.
  Comparison ignores spacing and variable names. It also prints char lists
  and one-character atoms the same way: the engine prints `"ab"` as Scryer's
  toplevel does, but `writeq/1` in a `-g` goal prints `[a,b]`. Files that end
  in `:- end_module/1` get the engine's own oracle prelude. The oracle's
  verdict is evidence. The class each difference gets is set in the fixture.
* **Fail closed.** The tool prints `N files read, M compared` and the depth
  breakdown below. It exits 2 when M is 0, and the gate also refuses a run with
  0 deep-compared files. A crashed child counts as a difference of kind
  `crash`, and that file is not counted as compared.
* **What is pinned.** `tests/fixtures/pl_parity_known.json` holds each
  difference with its class and note, plus a hash of each side's value.
  `tests/fixtures/pl_parity_native.json` holds native's full observation of
  every file (load, verdicts, answers) and a hash of the translator's.
  `--check` goes red on any of these:
  * a new or vanished difference;
  * a changed value inside a pinned row;
  * any change in native's observation of any file, native-only files
    included;
  * any change in the translator's hash.

  `--update` rewrites both fixtures. A new row gets class `?`, which the gate
  refuses until it is classified.

## Reading it

* Every load the translator refuses, the native front end accepts. No file
  regresses from loads to refused, except `dcg_grammar.pl`, and there native
  is the one that agrees with Scryer.
* For the files that only native loads, there is no translator side to
  compare against. Native's own answers are PINNED, so a later native change
  there goes red, but they are checked against the oracle only by the slice
  exit tests.
* The gate pins every row's values, and native's observation of every file. A new difference fails it, and so does a pinned
  row that disappears (prune the fixture). Rerun:
  `python -m clausal.tools.pl_parity --check tests/fixtures/pl_parity_known.json`
  (about 100 s with `-j 6`; `--check` skips the oracles).
