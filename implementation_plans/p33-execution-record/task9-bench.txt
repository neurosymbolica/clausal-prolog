Why head is a copy and not the worktree itself (a change from Tasks 2/4).  The
scratchpad sits on `overlay` and /workspace sits on `virtiofs`:

    $ df -T /tmp/claude-1000 /workspace/clausal-bug-fix
    overlay   overlay   ...  /
    mount0    virtiofs  ...  /workspace

bench_struct_tabling RELOADS the .clausal fixture inside the timed region
(three times), so a base-on-overlay vs head-on-virtiofs A/B puts a filesystem
difference inside the measurement and charges it to head.  Copying head to the
same filesystem removes that confound.  Run A below keeps the old shape (head =
the live worktree) as a cross-check; runs B and C are the same-filesystem
instrument and are what the gate is read from.

The two trees were then PROVEN to differ in exactly those 18 files and nothing
else (scratchpad/t9bench/verify_trees.py, recursive byte compare, __pycache__
excluded):

    differing files: 18   (all 18 expected, none unexpected)
    only in base: none    only in head: none
    expected-but-identical (no-op reverts): none
    TREES OK: True

Every bench process asserts `clausal.__file__` — AND `benchmarks.workloads.
__file__` — is under the tree it was told to measure BEFORE running any

clausal that a stray sys.path silently wins with), and echoes the resolved path
